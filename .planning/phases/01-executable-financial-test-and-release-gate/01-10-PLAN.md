<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Main/build → production | A successful merge/build must not grant production mutation authority. |
| Workflow dispatch → protected environment | User-supplied stage/evidence/feature inputs cross into production secrets and commands. |
| Receipt/artifact store → deployment target | Substituted or rebuilt artifacts could deploy unverified code. |
| Failure/rollback → database | Routine recovery could destructively rewrite financial facts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-14 | Tampering / Repudiation | build/evidence | mitigate | Build once, SHA-256, OIDC attestation, private readback receipt. |
| T-01-15 | Elevation of Privilege | promotion/enable environments | mitigate | Separate protected environments, explicit single-owner approvals, scoped secrets, one-stage dispatch, and accepted no-independent-reviewer risk. |
| T-01-16 | Tampering | stage chain/rollback | mitigate | Predecessor receipts, pinned digests, post-state checks, compensating receipts, forward DB repair. |
| T-01-SC | Tampering | workflow actions/artifacts | mitigate | Full-SHA actions, exact CLI, no rebuild during promotion. |
</threat_model>
