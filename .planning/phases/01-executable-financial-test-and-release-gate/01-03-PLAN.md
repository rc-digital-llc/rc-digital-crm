<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Baseline files → upgrade database | Checked-in SQL and history establish the trusted prior state. |
| Database rows → Node fingerprints | Type conversion or unstable ordering could hide financial changes. |
| PR diff → accepted baseline | A contributor could edit fixture and manifest together to rewrite history. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | baseline directory | mitigate | Per-file SHA-256 plus base-ref append-only enforcement; new version required. |
| T-01-04 | Tampering | upgrade orchestrator | mitigate | Exact canonical categories, text-preserved numerics, explicit transformations, zero retry. |
| T-01-07 | Information Disclosure | fixtures/reports | mitigate | Reserved synthetic data only and redacted mismatch output. |
| T-01-SC | Tampering | CLI/process chain | mitigate | Use pinned Plan 01 tools and explicit argv; no new package. |
</threat_model>
