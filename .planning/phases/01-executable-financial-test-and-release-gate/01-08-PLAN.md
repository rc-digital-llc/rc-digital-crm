<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Workflow/test reports → receipt | Untrusted/partial results could be presented as release proof. |
| Receipt → evidence repository | Public or mutable storage would disclose/substitute evidence. |
| Workflow input → approval/exception | A caller must not self-assert approval or bypass class. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-13 | Tampering / Repudiation | receipt builder/verifier | mitigate | Canonical JSON, SHA-256 ID, strict schema/policy, predecessor chain, attestation reference. |
| T-01-14 | Information Disclosure / Tampering | private publisher | mitigate | API-verified PRIVATE destination, immutable names, no clobber, authenticated readback. |
| T-01-02 | Spoofing | approvals/exceptions | mitigate | Consume protected deployment/reviewer identity; never workflow-input identity. |
| T-01-SC | Tampering | GitHub API tooling | mitigate | Runner-provided `gh`, explicit argv/API responses, no new package. |
</threat_model>
