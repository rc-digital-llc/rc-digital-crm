<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Caller metadata → Storage path | User filenames or tenant IDs could create traversal/cross-account objects. |
| Evidence state → signed access | Quarantined/rejected/expired/held bytes must never receive usable capabilities. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Tampering / Disclosure | bucket/object metadata | mitigate | Private bucket, no direct policy, server path, immutable scope. |
| T-02-11 | Elevation / Disclosure | access decision | mitigate | Caller-bound role/account/purpose/state check plus append event. |
| T-02-12 | Repudiation | access/inspection history | mitigate | Append-only events and compensating state transitions. |
| T-02-SC | Tampering | dependencies | mitigate | No new package; Supabase Storage is existing platform authority. |
</threat_model>
