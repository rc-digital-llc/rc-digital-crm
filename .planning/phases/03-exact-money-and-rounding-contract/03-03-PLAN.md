<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Legacy decimals/JSON → exact authority | Ambiguity or fractional values could be guessed or rounded. |
| Transformation registry → accepted drift | An overbroad entry could legitimize unrelated changes. |
| Legacy/exact write surface → stored facts | Contradictory dual writes could choose authority inconsistently. |
| Automation command → amount limit/effect | Numeric tokens or old RPC signatures could bypass exact limits. |
| Direct PostgREST → invoices base table | PostgreSQL coercion or raw bigint output could bypass string-token authority. |
| Idempotency key → recorded automation request | A conflicting tuple could be mistaken for an identical retry. |
| Exact bigint → compatibility decimal | A narrow legacy type could overflow or silently reduce the authoritative range. |
| New/changed tests → protected targets | Explicit Make lists could skip test 65 or inherited caller coverage. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-07 | Tampering | upgrade registry | mitigate | Ordered narrow categories, exact hashes/invariants, immutable prior artifacts. |
| T-03-08 | Tampering / Elevation | dual/RPC authority | mitigate | Exact-only write contract, revoke old numeric signature, derived projections, live tests. |
