<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| PostgREST/RPC JSON → application | Exact database integers could arrive as unsafe JavaScript numbers. |
| Browser/provider request → exact RPC | Loosely typed numeric or formatted values could regain authority. |
| FakeRest → tests/demo | Demo-only coercion could hide production contract bugs. |
| Invoice preview → operator | Fractional or differently rounded preview could misrepresent later authority. |
| Direct PostgREST → invoice base table | Coercion or raw bigint output could bypass exact projection/RPC validation. |
| New boundary/provider tests → protected targets | Explicit Make lists could omit tests despite their presence. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | HTTP JSON tokens | mitigate | Live type assertions, codec validation, numeric-token denial, exact postconditions. |
| T-03-02 | Tampering | adapter/preview arithmetic | mitigate | Branded types and central BigInt module only. |
| T-03-08 | Elevation | legacy numeric RPC | mitigate | Remove provider path/signature and assert denial/unchanged effects. |
| T-03-03 | Repudiation | preview policy | mitigate | Explicit version in input/result and shared golden vectors. |
| T-03-10 | Elevation / Tampering | invoice base-table access | mitigate | Live denial of GET/POST/PATCH; security-invoker exact view and checked JSONB RPC only. |
| T-03-12 | Tampering / DoS | compatibility projection | mitigate | Both signed endpoints, exact `numeric(19,2)` expectations, and one-step overflow rejection. |
| T-03-09 | Tampering / Repudiation | Wave 4 coupling | mitigate | Same-wave Make/classifier edits plus rolling static removal tests and permanent target execution. |
| T-03-SC | Tampering | provider dependencies | mitigate | No package changes; existing locked clients and test runner. |
</threat_model>
